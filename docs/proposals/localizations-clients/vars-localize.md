## 1. How the app touches localizations today

**Verdict: READER and WRITER (bounding boxes only).** vars-localize is a bounding-box editor and is the app the proposal names in section 11.1. It reads boxes from `observation.associations` where `link_name == "bounding box"`, parses the `link_value` JSON (integer pixels, optional `image_reference_uuid`, `observer`), and draws them on the framegrab pixmap. It writes boxes with `POST /associations` and `PUT`/`DELETE /associations/{uuid}`, with `link_name="bounding box"`, `mime_type="application/json"`, `to_concept` set to the organism "part" (the UI uses the literal `"self"` for no part: `ui/PropertiesForm.py:46,60`, `ui/BoundingBox.py:89`; the migration converts those legacy `'self'` values to NULL `part`), and a `link_value` of `{x,y,width,height,generator:"vars-localize",image_reference_uuid,observer}`. It does not touch points, lines, polygons or masks. It does not use ZeroMQ or any messaging. There is no annosaurus client library: `AnnosaurusClient` is a hand-written `requests` wrapper. No other localization link names, tags, `confidence` or `verifier` are read or written (the `confidence` hits are the SAM3 model threshold, unrelated).

## 3. Behavior and semantic changes to watch

- **Pixels to normalized.** The app's in-memory model is integer pixels on the framegrab (`SourceBoundingBox(QRect)`, `calc_crop_rect`, `PropertiesForm`). Normalizing on save is `x / pixmap_width`; denormalizing on load is `x * pixmap_width`. The pixmap size is already known at display time (`ImageView.pixmap_src`), so no extra lookups are needed. Avoid the float round-trip drift in the companion doc (`15/22*22 != 15`): round edges (floor min, ceil max, derive size), never origin and size independently.
- **Image display no longer needs dimensions from the server**, but any export or "find similar" feature that needs pixels on a different image (video frame vs framegrab) now works because coordinates are resolution independent. This removes the historical image-reference-scoping workaround (#6, #13).
- **Truncated boxes.** The app clamps drag-drawn boxes to the image (`calc_crop_rect`) but does not flag truncation. With the new `truncated` flag, decide whether a box touching an edge sets `truncated=true` (the proposal says the client clamps and sets it).
- **Confidence scale / tags.** vars-localize never writes `confidence` or `tags` (the `confidence` hits are the SAM threshold). Confidence is stored 0-1; the migration resolves the legacy scale per video (any value > 1 means the whole video is 0-100 and is divided by 100; existing 0-1 writers are not divided; uploads are per video, so a video does not mix scales), and the app ignores it, so no effect. Rule for any future write: send 0-1 only. `training` is not written today; the `group="ROV:training-set"` observation field is the only training signal, and `training` is the only tag.
- **One per (observation, type).** The app already enforces one box per observation client-side (`ImageView.py:2268-2278`), so behavior is aligned. A SAM "accept candidate" on an observation that already has a box must use upsert-with-409 deliberately, not silently overwrite.
- **409 handling.** Today modify is last-write-wins and silent. New flow: send `last_updated_timestamp`, on 409 reload and tell the user.
- **`part` and `difficult`.** `part` is a nullable free-text `varchar(128)` replacing `to_concept`, no validation (D-13); the app keeps its KB-driven picker. `difficult` is a new boolean, false for all migrated rows (D-16), which the app does not use.
- **Dropped `image_reference_uuid`.** `models/entries.py:75-82` currently hides a box drawn on image A when viewing image B of the same moment, and shows video boxes read-only. After cutover both appear on any image of the observation's moment. Migrated boxes whose image reference is orphaned fall back to the video's dimensions (not quarantined), so they are correct only if the media assumption holds (proposal 11.2). If a moment has several images with different aspect ratios, the proposal's media assumption (6.2) applies.
- **`generator`.** The app writes `"vars-localize"` (`BoundingBox.py:51`); keep it. Add `observer` (currently only set if non-None, `:55-56`), `observation_timestamp`, and `verifier` if the UI has a verification concept (it does not today).

## 4. Dependencies and ordering

1. annosaurus ships the localization endpoints and `Annotation.localizations` in the payloads vars-localize reads (`/imagedmoments/{uuid}`, `/fast/videoreference/{uuid}`, `/annotations/imagereference/{uuid}`, `/imagedmoments/videoreference/{uuid}`).
2. There is no annosaurus client library dependency (`pyproject.toml` has none; clients are in `services/clients.py`), so the update is hand-written. If the team publishes a Python client, adopt it instead.
3. Per proposal section 12, vars-localize must have a release ready before Phase 3 (cutover). It cannot be dual-mode: after cutover, `POST /associations` for boxes returns 400 and associations no longer contain boxes, so an unupdated app both fails writes and shows no boxes. Ship the update in Phase 2, gated on the new endpoints being live.
4. The query surface (`localized_annotations`, `/v1/localizations/query/*`) is for vars-gridview only (D-14); vars-localize does not depend on it. The `annotations` view no longer exposes localizations, and `/query` returns none.
5. Cutover date is TBD and will be announced once all apps are aligned; the release must still be ready beforehand. A new annosaurus client / SDK release is needed by other apps, but none is used here.
6. Optional compatibility: the app could feature-detect via `GET /v1/localizations/list/constraints` and fail with a clear "server too old/new" message.

## 6. Resolved and still open

**Resolved (from the revised proposal):**

- **R1 `part` (was the biggest risk): resolved.** D-13 adds free-text `part varchar(128)` replacing `to_concept`, no validation. Map to it (#8, #22).
- **R4 orphaned image references: resolved.** The migration falls back to the video's dimensions instead of quarantining; `image_reference_uuid` is dropped from localizations.
- **R6 `video_boxes` editability:** not decided by the proposal, but the image-reference distinction disappears, so it reduces to the ownership rule in #13 (still a product call, below).
- **R7 `observer`:** maps to the localization `observer` column; `observation_timestamp` is a client-supplied column (6.3).
- **Confidence (D-15), rule kept, mixed-scale risk resolved:** stored 0-1, migration decides per video, new writes must be 0-1. Uploads are per video (vars-cli `ml upload` writes 0-100, `ml upload-images` writes 0-1, one pipeline per video), so a video does not mix scales and the per-video rule cannot corrupt one. No pre-migration check is needed for this app, which never writes confidence.
- **`self` becomes NULL (D-13):** the migration stores NULL `part` for `'self'` (exact, case-sensitive); any other `to_concept` is copied verbatim. The no-part placeholder question is closed. Client change (#8, #22) is definite: send null/omit, display NULL as no-part, never write `"self"`.
- **Annotation create carries `localizations`:** `POST /v1/annotations` and `/bulk` accept them (same rules as the PUT, same transaction, an invalid localization fails the request). Creation stays one call and no create-then-PUT step or loss of atomicity arises. `PUT /v1/annotations/{uuid}` does not carry localizations (proposed); edits use `PUT /v1/localizations/{observation_uuid}/{type}` (#1, #2, #20).
- **No image columns, count endpoint:** `localized_annotations` has no `image_reference_uuid`, `image_url` or `image_format`; clients choose an image from `imaged_moment_uuid` via the existing image-reference endpoints. `POST /v1/localizations/query/count` lives in the `/v1/localizations/query/*` group. Not used by this app (#23).
- **`GET` image reference by uuid:** unaffected by the proposal. This app does not call it.
- **Bulk:** per-batch transactional, upsert by `(observation_uuid, type)`; not used by this app.
- **Query surface (D-14, 7.3):** new `localized_annotations` view and three endpoints, `/query` returns no localizations; not used by this app.
- **Masks / second tag / `SELECT` on `video_references`:** no mask link name; `training` is the only tag; annosaurus user has SELECT. None affects this app.
